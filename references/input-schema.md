# 数据字段与来源

后台页面名称可能随抖音创作中心版本变化；用户提供截图时，优先保留完整页面、作品标题和数据时间范围，避免只截一个数值。

## 0. 每次诊断都要有的元数据

| 字段 | 是否必填 | 数据来源 | 用途 |
|---|---|---|---|
| 账号名称或匿名编号 | 必填 | 用户填写 | 区分账号，不混样本 |
| 诊断目的 | 必填 | 用户填写 | 区分播放诊断、IP 承接或商业线索诊断 |
| 数据观察窗口 | 必填 | 用户填写 | 例如发布后 72 小时、7 天、30 天 |
| 是否投流 | 必填 | 用户填写/投放后台 | 自然流与投流不可直接混比 |
| 实际发布时间 | 必填 | 内容管理 | 控制发布时间与数据成熟度 |
| 视频总时长 | 必填 | 内容管理/作品详情 | 计算平均播放占比与分组 |
| 实际标题、封面、首帧 | 必填 | 内容管理截图 | 对照点击和前 2 秒表现 |
| 前 15 秒逐字稿或录屏 | 建议 | 用户提供 | 把留存节点映射回内容 |

## 1. 单条作品观看数据

来源：抖音创作中心 `内容管理` 中进入单条作品的数据详情或作品分析页。

| 字段 | 是否必填 | 用途 |
|---|---|---|
| 播放量 | 必填 | 计算总观看时长；判断规模，不单独判断质量 |
| 平均播放时长 | 必填 | 原方法作品层面第一优先指标 |
| 平均播放占比 | 必填或由时长计算 | 与平均播放时长配合；只在相近时长组比较 |
| 2 秒跳出率 | 必填 | 计算 2 秒存活与 2→5 秒相对留存 |
| 5 秒完播率 | 必填 | 计算 2→5 秒相对留存 |
| 完播率 | 必填 | 原方法作品层面最后看；不能跨时长单独比较 |
| 封面点击率 | 必填，后台有才填 | 评价卡片/双列/PC 等主动选择场景 |
| 封面曝光量 | 建议 | 没有曝光量时，封面点击率的稳定性未知 |
| 点赞、评论、收藏、分享 | 建议 | 补充消费与传播动作，不替代观看判断 |
| 新增关注 | 建议 | 补充关系转化，不替代主页访问 |

若需要计算原稿中的“5 秒后人群估算平均观看时长”，本表中的播放量、平均播放时长、2 秒跳出率和 5 秒完播率四项均为必填。用户可确认是否沿用原稿默认假设：2 秒前跳出者平均看 1 秒，2 到 5 秒跳出者平均看 3.5 秒。

## 2. 留存曲线

来源：同一作品的数据详情中的 `观众留存`、播放趋势或留存曲线。

必须提供完整曲线截图。若后台支持读取，附：0、2、5、10、15、30 秒和视频结束点的留存值，以及明显断崖对应时间。

用途：定位“前 5 秒以后”在哪个内容段落发生流失。曲线只能指出需要回看的位置，不能单独证明某句话是原因。

## 3. 流量来源

来源：单条作品 `流量来源` 页面。

| 字段 | 是否必填 | 原方法中的意义 |
|---|---|---|
| 推荐页播放/占比 | 必填 | 被动接收信息的入口，主要反映分发规模与观看表现 |
| 搜索播放/占比 | 必填 | 用户主动查找相关内容的入口；观察长尾和问题匹配 |
| 搜索词及播放 | 强烈建议 | 判断用户实际在找什么；没有词不能称为需求匹配 |
| 个人主页播放/占比 | 必填 | 用户进入主页后再点开该作品的播放，不等于主页访问量 |
| 关注、消息、同城、其他来源 | 建议 | 解释来源构成与异常变化 |

## 4. 账号周期数据

来源：抖音创作中心 `账号数据` 或数据总览，时间范围必须与作品复盘窗口一致或明确不同。

| 字段 | 是否必填 | 原方法中的意义 |
|---|---|---|
| 主页访问量 | 必填 | 原方法账号层面优先指标，表示用户进一步查看账号 |
| 播放量 | 必填 | 规模背景，不能替代吸引力 |
| 新增关注 | 建议 | 关系动作，不能替代主页访问 |
| 点赞、评论、分享、收藏 | 建议 | 互动背景，不能替代主页访问 |
| 主页访问来源/主页作品点击 | 建议 | 区分哪类内容带来进一步了解 |

## 5. 诊断服务可选业务字段

这些字段不属于原方法的抖音平台评价，但用户若希望从“平台表现”延伸到“商业承接”，必须另外提供，不能省略后由播放数据代替：

| 字段 | 数据来源 | 用途 |
|---|---|---|
| 视频带来的私信原话 | 抖音私信/客服记录 | 判断问题是否与业务有关 |
| 有效咨询人数 | 用户人工标注 | 区分泛互动与目标对象 |
| 进入私域人数 | 企微/表单 | 判断承接动作 |
| 预约与成交 | CRM/人工记录 | 不从播放数据反推成交 |
